**背景**: 「githubプロジェクト名を claude-code-history-viewer-for-JAPANESE にして」という依頼。調査の結果、GitHub リポジトリ名とビルド成果物のアプリ名は完全に別軸で、後者を変えるとインストール先が移動することが判明した。

| 選択肢 | 内容 | 採否 |

**帰結**: `qutto1/claude-code-history-viewer` → `qutto1/claude-code-history-viewer-for-JAPANESE`。ローカルの `origin` も更新済み。`productName` / `identifier` / Cargo の `name` はいずれも据え置き。

## 2026-08-30 「/routine 実行プロジェクトの非表示」と「環境フィルタ」の判定基準

**背景**: 左ペインに (a) `/routine` で実行されたプロジェクトを隠す機能と (b) 環境（ホスト名・クラウド等）で絞り込むドロップダウンを求められた。全 3,990 個の JSONL・117,569 行を走査した結果、**`/routine` の記録は 1 件も存在せず**、**ホスト名に相当する構造化フィールドもどこにも無い**ことが判明。実行環境を示せる唯一のフィールドは `entrypoint`（`claude-desktop` 66,155 / `sdk-cli` 20,049 / `cli` 43）だった。`sdk-cli` は market-forecast・spike-watch・sp500-watch の 3 プロジェクトにのみ現れ、他 7 プロジェクトはゼロ件という綺麗な分離がある。

| 選択肢 | 内容 | 採否 |
|---|---|---|
| entrypoint 自動判定＋手動上書き | `entrypoint` で自動分類しつつ、プロジェクトごとに環境ラベルとルーチン可否を手で上書きできるようにする。ホスト名が記録されない以上、別 PC やクラウドは手で名付けるしかない | **採用** |
| entrypoint 自動判定のみ | 実装最小。ただし別 PC を区別する手段が永久に無い | 不採用 |
| 手動マークのみ | 自動判定を持たず全て手で設定。10 プロジェクトなら現実的だが初期設定の手間が大きい | 不採用 |

**帰結**: `ClaudeProject` に `entrypoint` を追加（`extract_cwd_from_session_file` が既に開いているファイルから追加 I/O ゼロで取得）。`normalizeEntrypoint` に `sdk` カテゴリを追加し、本ユーザーの 3,489/3,896 セッション（89.6%）がバッジ無しになっていた既存バグも解消。手動上書きは既存の `ProjectContextMenu`（hide/unhide を持つ）を拡張。

## 2026-08-30 圧縮コンテキストの英和翻訳

**背景**: 「/compact の圧縮コンテキストに英和翻訳ボタンを追加、翻訳サイトは任せる」という依頼。実測調査の結果、API キー不要で実用に耐えるのは MyMemory のみ（LibreTranslate は公開 10 インスタンス全滅、Google 非公式は 13 リクエストで IP 遮断）。ただし 1 リクエスト 500 文字上限のため実データ（中央値 15,544 文字）で約 42 リクエスト・約 50 秒を要し、かつ**会話本文が第三者サーバーへ送信される**点を提示した。

| 選択肢 | 内容 | 採否 |
|---|---|---|
| コピーボタンに変更 | 翻訳は見送り、枠の右上に枠内全テキストをコピーするボタンを置く | **採用**（ユーザー提案） |
| MyMemory で実装 | 外部送信を承知の上で実装 | 不採用 |
| 送信前に確認ダイアログ | MyMemory で実装するが初回に同意を挟む | 不採用 |
| 翻訳を見送る | 何も追加しない | 不採用 |

**帰結**: `CompactSummaryRenderer` のヘッダー右端に「全文をコピー」ボタンを追加。折りたたんだ状態でもコピーできる。外部通信は一切追加していない（`tauri.conf.json` の `connect-src` は変更なし）。

## 2026-09-02 コミット追加時のバージョン運用

**背景**: `v1.26.3-fork.1` リリース後、圧縮コンテキストのフィルタトグル機能（コミット `ebbb252`）を追加した際、バージョン番号を変えずに GitHub Release のインストーラーとノートだけ差し替えた。この運用を今後も続けるか、コミットごとにバージョンを分けるかを問うた。

| 選択肢 | 内容 | 採否 |
|---|---|---|
| 同じタグに上書き | バージョン番号は据え置き、`gh release upload --clobber` で資産だけ最新化する。タグ・バージョン数が増えない | 不採用 |

**帰結**: 以後、`package.json` / `src-tauri/tauri.conf.json` / `src-tauri/Cargo.toml` / `Cargo.lock` の fork 番号を機能追加のたびに繰り上げ、新しいタグ・GitHub Release を作成する運用に変更。既存の `v1.26.3-fork.1` はそのまま据え置き、次回から `-fork.2` を起点とする。

## 2026-11-12 upstream v1.32.2 の取り込み（衝突解消の方針）

**背景**: 「upstream の最新バージョンのコードを取り込んで」という依頼。フォーク元（v1.26.3）から upstream は 112 コミット進んでおり、フォーク側 23 コミットとの間で 38 ファイルが衝突した。フォークは「メッセージ情報を左ガターへ移す」「展開したプロジェクトを全部開いたままにする」など UI の骨格を変えており、upstream は同じ領域（ヘッダー統合・Sessions ペイン・Temporary locations）を別の形で作り直していた。ユーザーが個々の衝突について判断したわけではなく、以下は私が下した判断である。

| 論点 | 選択肢 | 採否 |
|---|---|---|
| メッセージ情報の置き場 | フォークの左ガターを維持し、削除済みの `MessageHeader.tsx` / `AssistantMessageDetails.tsx` への upstream 変更（`ModelLifecycleBadge`、`text-warning`）をガターへ移植 | **採用** |
| | upstream のヘッダー行へ戻す | 不採用（ターン別コスト・effort の強調が消える） |
| 展開プロジェクトの全表示（フォーク機能） | `inlineSessions` が true のときだけ表示。lg 以上で Sessions ペインが出る既定幅では upstream の「選択中だけペインに出す」設計を優先 | **採用** |
| | 常にツリー内へ全表示（ペインと二重表示になる） | 不採用 |
| `compact_boundary` の表示 | upstream の「折りたたみ＋検索ヒットで自動展開」へ寄せ、フォーク独自の `durationMs` 表示だけ足す | **採用** |
| | フォークの「常に開いたカード」を維持 | 不採用（引き継ぎ内容の可読化は `isCompactSummary` 側の機能が担う） |
| タイマー自動更新 | upstream がヘッダーの更新ボタンを `refreshAllConversations` 1 つに統合し `refreshCurrentSession` を削除したので、タイマーも同じ関数に付け替える | **採用** |
| | `refreshCurrentSession` をフォーク側で復活させる | 不採用（ボタンと別経路になり「ヘッダーと同じ更新」という設定画面の説明に反する） |
| バージョン | `1.32.2-fork.1`（以後コミットごとに `-fork.N`） | **採用** |

**帰結**: 取り込み後に、フォーク独自機能 6 領域（/compact の表示とトグル、タイマー自動更新、環境表示とフィルタ、左ガターとコスト・effort、ツリーの複数展開、ビルド設定）を機能ごとに独立監査し、コード・配線・テストが残っていることを確認した（実際の画面は未確認）。見た目や挙動が変わるのは次の意図的な変更だけ。
- 展開プロジェクトの全表示は、Sessions ペインが出る lg 以上かつプロジェクト選択中は見えない（それ以外は従来どおり）。
- 連続する同モデルのターンでは、ガターの時刻・モデル行が省かれる（コストと詳細は残す。effort だけ変わったときは強調のため残す）。
- `compact_boundary` の本文は折りたたみの中に移った。
- タイマー自動更新は、選択中プロジェクトだけでなく全プロジェクトの再スキャンを伴う（ヘッダーのボタンと同じ）ので、1 回が重くなった。
監査で次の 2 点も見つかり、同じコミットで直した。
- **自動アップデータは実際には無効になっていなかった**（フォーク 1.26.3-fork.1 以来）。Tauri v2 の updater プラグインには `active` という設定項目が無く、`active: false` は黙って無視される。エンドポイントも pubkey も upstream のままで、フロントの自動チェックは起動時に走るため、SemVer で `-fork.N` は同番号の正式版より小さい以上、upstream 版が「新しい更新」として提示され、承認すればフォークが upstream に置き換わる状態だった。エンドポイントをフォーク自身のリポジトリ（latest.json を公開しない）に向けて塞いだ。テストも「upstream を指さない」ことを検証するよう強化した。
- upstream の継続行の高さ補正（-28px）は、ヘッダーが本文の上に独立した行としてある前提で、ガター配置のフォークでは行が縮まない。初回描画の高さ推定が実高さを下回りスクロールバーが跳ねるため、補正を外した。
Rust テストの失敗 6 件はすべて OS エラー 1314（この PC でシンボリックリンクを作れない）で、取り込みとは無関係。フォークのテストが `/tmp/...` を使っていたのが upstream の Temporary locations グループに入って失敗したため、テスト側を `/work/...` に直した。

## 2026-11-12 GitHub Copilot のメッセージ別コスト表示

**背景**: 「Claude Code で各メッセージの推定コストを表示するようにしたが、GitHub Copilot でも表示して」という依頼。upstream は Copilot を意図的に価格推定しない（`SOURCE_COST_ONLY_PROVIDER_IDS`。サブスクリプションなのでトークン数から請求額を再構成できない）。実データを調べると、VS Code Copilot Chat のログには入力トークンがあるが、`result.usage` は**最後のモデル呼び出し 1 回分**だった（手元の 1 リクエストは 21 回呼び出し・115 秒で、記録は 24,262 / 370 トークン）。Copilot CLI は出力トークンしかディスクに残らない。実装後の独立レビューで、実装者の「推定は高めに出る」が逆（実際は 1 桁以上低い下限値）だと分かり、方針を改めた。

| 選択肢 | 内容 | 採否 |
|---|---|---|
| ガターだけ API 定価換算の推定を出し、ツール呼び出しのあるターンは下限値（`≥`）にする | 分析画面は変えない。CLI は出さない。注記で請求額ではないと明示 | **採用** |
| upstream 方針どおり推定しない | 依頼に反する | 不採用 |
| 全ターンを同じ「推定（`~`）」で出す | 手元の例では実額の 1/10 以下の数字が完全な値に見える | 不採用 |
| CLI も出力トークンだけで推定する | 部分コストが誤解を招く | 不採用 |

**帰結**: `LIST_PRICE_ESTIMATE_PROVIDER_IDS`（`messageCost.ts`）で Copilot だけをオプトインし、分析側の価格ゲートは変えない。Rust では `result.usage` → `result.metadata` の順に項目ごとに読む（以前はトップレベルの `completionTokens` だけで、現行の VS Code ではトークンが全く取れていなかった）。Auto モードは結果の詳細に出るモデル名で `copilot/<モデル>` に解決する。副作用として Copilot のトークン統計に入力トークンが入るが、ツールを使ったターンは最後の 1 回分だけで過小になる。手元の実データは 1 リクエスト（エージェントモード）だけで、他のモデル名・単発のやり取りでの確認は取れていない。
